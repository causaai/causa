══════════════════════════════════════════════════════════════════════════════

📊 KEY DECISIONS:

1. ✅ Only keyEvidence (3-5 items) in main API response
   Why: UI team requirement - lean response, fast load

2. ✅ Evidence at root level (not nested in validation)
   Why: User needs quick access, not buried in nested objects

3. ✅ Include missing evidence
   Why: Transparency, identify observability gaps

4. ✅ Store full collection in DB
   Why: Can provide full evidence via separate endpoint if needed

5. ✅ Use metadata Map<String,String>
   Why: Flexible for different sources (query, pod, rule ID, etc.)

6. ✅ Source = WHERE (MCP server), Type = WHAT (data kind)
   Why: Clear distinction - source is system providing data (KUBERNETES_MCP),
        type is what the data is (CONTAINER_STATUS, METRIC)
