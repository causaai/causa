# Causa RCA Analysis Observability Integration Architecture

## Objective

Enable observability platforms such as Datadog, Grafana, Instana, Dynatrace, Prometheus, and other OpenMetrics-compatible tools to consume RCA analysis information generated by Causa and create monitoring, alerting, dashboards, and notifications.

The goal is to provide proactive visibility into RCA generation and allow users to navigate directly from alerts to RCA analysis details.

---

## Architecture Overview

```text
+------------------+
|   Causa Backend  |
+------------------+
          |
          | Expose RCA Metrics
          v
     /q/metrics
          |

+---------+------------------------------------------------+
|                                                          |
v                                                          v
Datadog Agent                                       Prometheus
(OpenMetrics Scrape)                                (Scrape)
|                                                          |
v                                                          v
Datadog                                              Grafana
Monitors & Alerts                                    Dashboards

Future:
- Instana
- Dynatrace
- New Relic
- Other OpenMetrics-compatible tools
```

---

## Assumptions

1. **Causa remains vendor-neutral** and does not implement Datadog-specific, Grafana-specific, Instana-specific, or Dynatrace-specific integrations.

2. **Causa exposes RCA metrics** through the standard Quarkus OpenMetrics endpoint:
   ```
   /q/metrics
   ```

3. **All observability clients** consume RCA information by scraping the metrics endpoint.

   Examples:
   - Datadog Agent (OpenMetrics integration)
   - Prometheus
   - Grafana
   - Instana
   - Dynatrace
   - New Relic

4. **Alerting, dashboards, routing, notifications, and monitor configuration** are owned by the observability platform and not by Causa.

## Required RCA Metrics

### 1. RCA Analysis Available

**Metric:**
```
causa_rca_analysis_available
```

**Type:** Gauge

**Value:**
```
1 = RCA analysis available
```

**Required Labels:**

| Label       | Description                    | Example                           |
|-------------|--------------------------------|-----------------------------------|
| analysis_id | Unique RCA analysis identifier | "2178940"                         |
| namespace   | Namespace where issue occurred | "causa-datadog"                   |
| workload    | Workload name                  | "auth-cache"                      |
| pod         | Affected pod                   | "fake-causa-app-6c5744b7dd-44lhd" |
| issue_type  | Issue category                 | "high_memory"                     |
| severity    | Severity level                 | "critical", "warning", "info"     |
| status      | Analysis status                | "triggered", "completed", "failed"|

**Example:**
```
causa_rca_analysis_available{
  analysis_id="2178940",
  namespace="causa-datadog",
  workload="auth-cache",
  pod="fake-causa-app-6c5744b7dd-44lhd",
  issue_type="high_memory",
  severity="critical",
  status="triggered"
} 1
```

### 2. RCA Analysis Duration

**Metric:**
```
causa_rca_analysis_duration_seconds
```

**Type:** Histogram

**Purpose:**
- Detect slow RCA generation
- Monitor RCA performance
- Track P50, P95, P99 latencies

**Labels:**
- `analysis_type`
- `status`
- `namespace`

**Example:**
```
causa_rca_analysis_duration_seconds_bucket{analysis_type="high_memory",status="completed",namespace="causa-datadog",le="0.5"} 10
causa_rca_analysis_duration_seconds_bucket{analysis_type="high_memory",status="completed",namespace="causa-datadog",le="1.0"} 25
causa_rca_analysis_duration_seconds_sum{analysis_type="high_memory",status="completed",namespace="causa-datadog"} 45.2
causa_rca_analysis_duration_seconds_count{analysis_type="high_memory",status="completed",namespace="causa-datadog"} 30
```

---

### 3. RCA Analysis Failures

**Metric:**
```
causa_rca_analysis_failed_total
```

**Type:** Counter

**Purpose:**
- Detect RCA generation failures
- Track failure reasons

**Labels:**
- `reason` (e.g., "timeout", "data_unavailable", "llm_error")
- `analysis_type`
- `namespace`

**Example:**
```
causa_rca_analysis_failed_total{reason="timeout",analysis_type="high_memory",namespace="causa-datadog"} 3
```

---

### 4. RCA Analysis Completed

**Metric:**
```
causa_rca_analysis_completed_total
```

**Type:** Counter

**Purpose:**
- Track successful RCA generation
- Calculate success rate

**Labels:**
- `analysis_type`
- `severity`
- `namespace`

**Example:**
```
causa_rca_analysis_completed_total{analysis_type="high_memory",severity="critical",namespace="causa-datadog"} 42
```

## RCA URL Handling

**Problem:** Including full RCA URLs as metric labels creates high-cardinality metrics, which can overwhelm observability platforms.

**Solution:** Use `analysis_id` as a label instead of the full URL.

**Recommended Approach:**

Metric label:
```
analysis_id="2178940"
```

Observability tools generate links using a template:
```
https://<causa-host>/analysis/{analysis_id}
```

**Example:**
```
https://irb.causa.com/analysis/2178940
```

This approach:
- Keeps cardinality low
- Allows dynamic URL generation
- Supports different environments (dev, staging, prod)
- Works with any observability platform

## Expected Alert Use Cases

### 1. New RCA Analysis Generated

**Trigger:**
```
causa_rca_analysis_available > 0
```

**Alert includes:**
- Analysis ID
- Namespace
- Workload
- Pod
- Issue Type
- Severity

**Action:** Navigate to RCA analysis page using analysis_id

---

### 2. Critical RCA Generated

**Trigger:**
```
causa_rca_analysis_available{severity="critical"} > 0
```

**Examples:**
- Memory leak detected
- OOMKill event
- CrashLoopBackOff
- Service outage

**Action:** Immediate investigation required

---

### 3. RCA Generation Failure

**Trigger:**
```
increase(causa_rca_analysis_failed_total[5m]) > 0
```

**Alert includes:**
- Failure reason
- Analysis type
- Namespace

**Action:** Investigate Causa backend health

---

### 4. RCA Generation Latency High

- Namespace

## Ownership

### Causa Platform Responsibilities

- Define and expose RCA metrics via `/q/metrics`
- Maintain OpenMetrics endpoint availability
- Ensure metric schema stability
- Document metric definitions and labels
- Version metrics appropriately
- Provide metric examples

### Observability Platform Responsibilities

- Configure Datadog OpenMetrics scraping (datadog.yaml)
- Create monitors and alert templates (monitor-config.json)
- Configure dashboards and notifications
- Provide RCA deep links from alerts
- Manage alert routing and escalation
- Maintain observability platform configuration
