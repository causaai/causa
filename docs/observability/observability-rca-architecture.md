# Causa RCA Analysis Observability Integration Architecture

## Objective

Enable observability platforms such as Datadog, Grafana, Instana, Dynatrace, Prometheus, and other OpenMetrics-compatible tools to consume RCA analysis information generated by Causa and create monitoring, alerting, dashboards, and notifications.

The goal is to provide proactive visibility into RCA generation and allow users to navigate directly from alerts to RCA analysis details.

---

```text
+------------------+
|   Causa Backend  |
+------------------+

Datadog                                              Grafana
Monitors & Alerts                                    Dashboards

Future:
- Instana

- New Relic
- Other OpenMetrics-compatible tools
```

---

## Assumptions

1. **Causa remains vendor-neutral** and does not implement Datadog-specific, Grafana-specific, Instana-specific, or Dynatrace-specific integrations.

2. **Causa exposes RCA metrics** through the standard Quarkus OpenMetrics endpoint:
   ```
   /q/metrics
   ```

3. **All observability clients** consume RCA information by scraping the metrics endpoint.

   Examples:
   - Datadog Agent (OpenMetrics integration)
   - Prometheus
   - Grafana
   - Instana
   - Dynatrace
   - New Relic

4. **Alerting, dashboards, routing, notifications, and monitor configuration** are owned by the observability platform and not by Causa.

## Monitors Implemented

### 1. Causa RCA Generation Failure

**Purpose:**
Triggers when RCA generation failures are observed.

**Details:**
- Uses failure metrics and surfaces failure reason and analysis type
- Intended to catch backend, data collection, or processing issues

**Configuration:**
`src/main/java/com/causa/observability/datadog/monitors/failure/monitor-config.json`

---

### 2. Causa RCA Generation Latency High

**Purpose:**
Triggers when RCA generation duration exceeds the configured threshold.

**Details:**
- Intended to identify performance degradation in RCA generation

**Configuration:**
`src/main/java/com/causa/observability/datadog/monitors/latency/monitor-config.json`

---

### 3. Causa RCA - High Failure Rate

**Purpose:**
Tracks the overall volume/rate of RCA generation failures.

**Details:**
- Useful for identifying systemic issues rather than individual failures

**Configuration:**
`src/main/java/com/causa/observability/datadog/monitors/high-failure-rate/monitor-config.json`

---

### 4. Causa RCA - No Analysis Generated

**Purpose:**
Alerts when no RCA analyses are generated within a defined time window.

**Details:**
- Intended to detect pipeline outages, ingestion failures, or backend issues

**Configuration:**
`src/main/java/com/causa/observability/datadog/monitors/no-rca-generated/monitor-config.json`

---

### 5. Causa RCA - Slow Analysis Trend

**Purpose:**
Detects increasing RCA generation duration trends over time.

**Details:**
- Intended as an early warning for performance degradation

**Configuration:**
`src/main/java/com/causa/observability/datadog/monitors/slow-rca-trend/monitor-config.json`

---

### 6. Causa RCA Success Rate Low

**Purpose:**
Triggers when the RCA success rate falls below the configured threshold.

**Details:**
- Helps identify an increase in RCA generation failures relative to successful analyses
- Intended to detect reliability issues in the RCA generation pipeline and backend services

**Configuration:**
`src/main/java/com/causa/observability/datadog/monitors/success-rate/monitor-config.json`

## RCA URL Handling

**Problem:** Including full RCA URLs as metric labels creates high-cardinality metrics, which can overwhelm observability platforms.

**Solution:** Use `analysis_id` as a label instead of the full URL.

**Recommended Approach:**

Metric label:
```
analysis_id="2178940"
```

Observability tools generate links using a template:
```
https://<causa-host>/analysis/{analysis_id}
```

**Example:**
```
https://irb.causa.com/analysis/2178940
```

This approach:
- Keeps cardinality low
- Allows dynamic URL generation
- Supports different environments (dev, staging, prod)
- Works with any observability platform

## Expected Alert Use Cases

### 1. New RCA Analysis Generated

**Trigger:**
```
causa_rca_analysis_available > 0
```

**Alert includes:**
- Analysis ID
- Namespace
- Workload
- Pod
- Analysis Type
- Severity

**Action:** Navigate to RCA analysis page using analysis_id

---

### 2. Critical RCA Generated

**Trigger:**
```
causa_rca_analysis_available{severity="critical"} > 0
```

**Examples:**
- Memory leak detected
- OOMKill event
- CrashLoopBackOff
- Service outage

**Action:** Immediate investigation required

---

### 3. RCA Generation Failure

**Trigger:**
```
increase(causa_rca_analysis_failed_total[5m]) > 0
```

**Alert includes:**
- Failure reason
- Analysis type
- Namespace

**Action:** Investigate Causa backend health

---

## Ownership

### Causa Platform Responsibilities

- Define and expose RCA metrics via `/q/metrics`
- Maintain OpenMetrics endpoint availability
- Ensure metric schema stability
- Document metric definitions and labels
- Version metrics appropriately
- Provide metric examples

### Observability Platform Responsibilities

- Configure Datadog OpenMetrics scraping (datadog.yaml)
- Create monitors and alert templates (monitor-config.json)
- Configure dashboards and notifications
- Provide RCA deep links from alerts
- Manage alert routing and escalation
- Maintain observability platform configuration
